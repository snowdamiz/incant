No actionable blocker found in the frozen foundation. Source-only review; no edits, new builds, provider requests, native windows or graphics were performed.

The lease cannot escape `reserve` before the conservative cumulative cap is serialized, the temporary record is synced, and the replacement succeeds (plus parent-directory sync on Unix). The persistent, per-project OS lock remains owned by the ledger/lease throughout the turn; completion consumes that owner. Abrupt exit or dropping without a receipt retains the full pending cap. Wrong-cap or decreasing cumulative receipts return before writing, retaining the reservation. Over-cap measured usage remains charged, and saturation at the JavaScript-safe cap exhausts every representable allowance. Prior uncertainty cannot be erased by a later successful receipt.

The reader bounds records to 4096 bytes, refuses malformed/unknown fields, versions, foreign project identities, unsafe counts and inconsistent pending reservations, and never silently resets those records. Canonical bounded ULID filenames prevent project-input path traversal; record/lock symlinks and non-files are refused. Distinct projects have separate lock and accounting identities. The same-owner user-data directory is outside undoable project content, so project Undo and provider account/build changes do not reset recorded usage.

The tests exercise real child-process abrupt exit, live OS lock exclusion and completed receipt recovery, alongside exact on-disk-before-lease, invalid receipt, cap reduction, uncertainty persistence, unsafe count, malformed-record preservation and path/file refusal controls.
