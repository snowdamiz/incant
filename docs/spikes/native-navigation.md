# Cooked native navigation

This slice moves NavigationMesh and NavigationGrid into the disposable native
world. It reuses incant_nav's pinned rerecast 0.4.0 tile builder, A*/funnel,
off-mesh links and weighted grid search. It adds no legacy gameplay, script
bindings, renderer/debug draw or appearance changes. PLAN 2.6 and Phase 1 still
require the remaining SDK, steering integration and device evidence.

## Boundaries and APIs

- `CookedScene::with_navigation(Vec<CookedNavigation>)` checks typed declarations,
  source bindings, final hierarchy and derived geometry before publishing a world.
  Owners/sources/links use binary StableId values. Mesh geometry is embedded in
  local source coordinates with a model recipe descriptor; collider geometry is
  generated by the existing converter now below authoring in
  `incant_physics_runtime::navigation_geometry`. The old physics facade reexports
  that same implementation.
- `cook_scene` supports grids and collider sources. Mesh sources require explicit
  `cook_scene_with_navigation(project, scene_id, &NavigationResources)`. Missing
  or stale recipes fail with `CookError::NavigationResource`; no empty geometry
  fallback or project filesystem lookup occurs in the native world. Existing
  checked asset-store providers can supply these authoring-side resources.
- `prepare_script_scene_with_navigation(project, scene_id, resources)` binds the
  same checked scene and geometry to the authored-script source catalog and
  attachment set. It returns the existing PreparedScriptScene package; compile
  produces the existing paired CookedScene/CompiledScript. The default
  `prepare_script_scene` retains strict missing-resource refusal. No source is
  silently removed and no runtime source compiler is introduced.
- `NativeWorld::{navigation_path, grid_path, navigation_report}` query retained
  checked state. Owned paths carry the world-local navigation generation;
  retained reports describe the last actual rebuild. These are native Rust APIs,
  not granted guest capabilities. The command buffer adds boxed `SetNavigation`
  for explicit replace/remove at the existing exclusive sync point.

Geometry providers are trusted authoring adapters. Recipe fingerprints detect
accidental binding mismatch; they are not authentication or proof that arbitrary
caller-supplied geometry came from an asset. The cooked envelope checksum detects
corruption, not authorship. Runtime loading uses checked values, never layout
casts or executable bytes.

## Retention and transaction behavior

A structural change stages final parent/configuration/body/asset state, source
geometry and all changed tiles before any ECS or solver publication. The source
and its ancestors must have no nonzero Velocity and no moving 2D/3D body. A fixed
body or ordinary static entity is allowed. This restriction ensures solver
advancement cannot make a successfully preflighted navigation source move later
in the same tick. Intentional numeric source-pose edits remain supported at the
explicit sync boundary; moving-body obstacle avoidance is not added here.

The structural boundary expands a bounded set of source/ancestor dependencies.
Ordinary unchanged ticks compare that set and retained source globals; they do
not walk ancestors, clone geometry/world/project, serialize JSON or revalidate
whole grids. Grid validation and minimum-weight calculation happen once in an
immutable PreparedGrid. Queries still allocate the existing bounded search
frontier/result arrays; this is not a zero-allocation query or whole-frame claim.

Changed poses rebuild into staged state using the existing dirty-tile cache.
Stable ULID/kind source keys keep unrelated triangle order stable across source
insertion/removal. Settings hashes use canonical numeric bytes instead of JSON.
Unchanged tiles retain shared storage. Rebuild CPU time remains synchronous host
work; no background job or deadline/preemption guarantee is claimed.

Numeric edits make queries explicitly refuse until successful `apply` or `step`,
so callers cannot silently observe old geometry against new source poses. A bad
structural batch preserves the queue, ECS and published navigation. The real
QuickJS host revokes loans and restores numeric undo on a late navigation rebuild
rejection, caught deferred work or exception. Failed preflight steps preserve the
clock and old derived state; existing post-solver failure remains terminal.

Despawn removes owner declarations. Despawning a still-referenced source refuses
unless its final configuration removes that reference in the same batch. A later
plain spawn reusing the stable ID does not resurrect navigation. Reparenting,
zero-Velocity archetype relocation and final-value command semantics use the same
staged boundary. The initial navigation slice refused navigation saves.
[Retained world checkpoints](native-retained-saves.md) now preserve checked
navigation in version 2; legacy version-1 restore still refuses to clear a
world's navigation history. Physics/audio continuation remains unsupported.

## Binary v9 and limits

Only nonempty navigation selects cooked scene v9. Scenes without navigation keep
the previous v1–v8 selection and encoding paths unchanged. V9 appends canonical
owner/source/link tables after the existing v8 tables. All fields use checked
little-endian encodings; floats are finite f32 with positive-zero canonical form.
Local/global ECS transforms remain continuous f64; navigation's existing raster
geometry/path precision stays f32. Mirrored source transforms preserve walkable
winding through the existing checked geometry transform.

The loader rejects malformed masks/tags/booleans, duplicate or unsorted IDs,
noncanonical floats, impossible counts/indices, truncated/trailing bytes, stale
asset references and invalid final topology. Count/remaining-byte and aggregate
geometry/grid/link budgets precede decoded vector allocation. The 128 MiB scene
limit includes every v9 suffix and the v8 count even when there are no flipbooks.
The existing conservative 128-byte-per-entity accounting remains in place.

Aggregate native scene limits are:

| Resource | Limit |
| --- | ---: |
| Mesh declarations / grid declarations | 8 / 8 |
| Source records / unique source and ancestor dependencies | 1,024 / 4,096 |
| Source vertices / triangles (including collider expansion) | 98,304 / 32,768 |
| Tiles / links across all meshes | 256 / 128 |
| Derived polygons / detail triangles across all meshes | 32,768 / 262,144 |
| Grid cells across all grids | 65,536 |

Each builder also retains its existing 8,000,000 projected-cell-visit refusal,
voxel precision/height limits and query expansion/path caps. Staging temporarily
retains old and candidate storage, and one bounded candidate can exist before the
derived aggregate limit rejects it. These caps are safety bounds, not measured
phone memory or frame budgets.

## Local verification and remaining work

On macOS arm64/Rust 1.99.0, 188 tests/doctests across incant_runtime, incant_nav,
incant_physics, incant_physics_runtime and incant_cook pass in the CI profile;
all-target Clippy with warnings denied passes. The authoring-free normal graph
check passes for runtime/nav/physics_runtime. wasm32-unknown-unknown compilation
passes; this is compile-only, not browser execution or mobile/device parity.

Seventeen new behavior tests cover source-free mesh/collider/grid paths, actual
script-program composition, dirty-tile reuse after pose and source removal,
mirrors/f64 parent transforms, link enable/disable, malformed checksum-valid
binary data, aggregate capacities, hierarchy/archetype/despawn/ID reuse,
transaction/loan rollback and save refusal. Existing algorithm and legacy-facade
checks remain included. Logs/hashes are in
[evidence/native-navigation-2026-10-11.json](evidence/native-navigation-2026-10-11.json).

Root SDK integration, standard host cache-provider wiring, steering/avoidance
world integration, automatic tilemap-to-grid policy, debug draw, complete session
saves and shipped reference-phone measurements remain open. This local evidence makes no Phase 1 completion or performance-gate claim.
