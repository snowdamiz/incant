# Phase 1: static model import and cooking

2026-10-09. This is the first asset-pipeline increment after the director authorized
Phase 1; it does not complete the asset pipeline or pass a phase gate.

## Implemented path

`incant_assets` imports static, untextured glTF 2.0 and GLB models on the CPU. It
retains scene roots, node hierarchy and local transforms, primitive-to-material
bindings, and standard material JSON. Triangle geometry carries position, normal,
UV0 and tangent data. Missing normals generate flat triangle normals, retaining
hard edges. Meshopt 0.6.2 optimizes vertex/cache order and compresses vertex and
index streams. The decoder returns the same optimized representation for newly
cooked files and cache hits.

Run from the repository, with the source path relative to the project file:

```sh
tools/cargo run -p incant_headless --release --locked -- import /path/to/game.incant.json models/prop.glb
```

The default cache is `.incant/cache/models` beneath the project directory; `--cache`
selects another directory. A model manifest and its compressed meshes live in one
versioned binary `.incmodel` file. Binary geometry stays outside project JSON.
`load_model(cache, fingerprint)` loads this representation without source files;
this is a CPU loader, not yet integrated into the renderer or ECS asset system.

The cache key includes the importer/codec version and the sorted dependency paths
and SHA-256 hashes. Each import reads its source and external buffers before
considering a cache hit. Changing an external buffer invalidates the model even
when its glTF JSON is unchanged. Currently the hit path still parses geometry;
avoiding that CPU work is an optimization remaining for a later increment.
Files have bounded lengths, explicit versions and checksums. Writes use a synced
temporary file and atomic replacement. Damaged entries are rejected by the loader
and regenerated by the importer. Old entries remain available for undo; cache
retention/garbage collection is not implemented yet.

Source resolution accepts local external buffers, base64 data URIs and GLB chunks.
Percent-decoded sibling paths can stay within the project. Network URLs, absolute
paths, traversal outside the project and resolved symlinks outside it are rejected.
Sources are limited to 128 MiB, one million vertices and three million indices;
node, primitive and dependency counts are also bounded. These are initial limits,
not measured streaming/performance budgets.

## Authoring integration

`UpsertAsset` and `RemoveAsset` use the existing atomic command bus. Validation of
the entire final project permits importing metadata and scene references in one
transaction and prevents removing a referenced asset alone. Import provenance is
recorded on the transaction. Reimport keeps the asset ULID and name; undo restores
the previous fingerprint. Unchanged CLI imports create no extra history entry.
CLI history survives process restarts in the normal project journal. The generated
command schema, agent tool schema and TypeScript bindings include the new commands.
This does not yet add a provider-facing `asset.import` tool or editor asset browser.

## Verification

Local checks passed:

- Six pipeline tests cover external/embedded buffers, GLB, source-independent
  cooked loading, external-buffer invalidation, corrupt/truncated cache handling,
  malformed geometry, hierarchy cycles, URI confinement, and hard-edge normals.
- Three command-bus asset tests cover shared import/reference transactions,
  removal validation, stable identity and undo/redo, and failure atomicity.
- The CLI integration test imports across separate processes, checks a no-op hit,
  changes source geometry, preserves identity and reopens the journal to undo.
- Existing eight command transaction tests (including 10,000 undo sequences),
  seven document tests and two headless evaluation tests pass.
- Affected-crate Clippy with warnings denied, formatting, generated convention/SDK
  checks and strict SDK TypeScript compilation pass.

The code ran without a browser, renderer capture, account or credential access.
Hosted workspace/platform validation is pending on the Phase 1 draft PR.

## Remaining Phase 1 work

The importer explicitly rejects glTF textures/images, skins/animation, morph
positions, sparse accessors, extension-based features, non-triangle primitives,
cameras, vertex colors and UV sets beyond UV0. It does not silently claim support.
FBX conversion, PNG/JPG/EXR and WAV/OGG import, KTX2 texture cooking, asset streaming,
automatic file watching/runtime hot reload, the editor/agent import entry points,
and rendered integration remain to implement. The rest of Phase 1 (renderer,
physics, audio, animation, UI, expanded scripting/input and Core Sample) remains
open in PLAN.md.
