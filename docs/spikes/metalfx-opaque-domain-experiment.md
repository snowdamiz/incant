# Explicit opaque scene background: private MetalFX experiment

This source is a test-only successor of raw diagnostic 0a59afd. It has no public API, default enablement, adoption, visual acceptance or timing claim. The earlier transparent capture and failed map-size postcheck remain retained under `~/.codex/incant-evidence/metalfx-raw-diagnostic-001`. Its proposal002 SHA256 is be3891c495d29f0d982650cc4df65673be20d693c3aa9080d38a017c8e5ca6cb.

The captured vendor alpha was exactly one, including background. We therefore do not use it as coverage. The transparent adapter additionally rejects reconstructed edges whenever the low-resolution current footprint is clear or crosses depth. Original transparent shaders and admission remain unchanged; a CPU byte-identity check binds their assembled source.

The private experiment declares real scene-linear constant background radiance `[0.02, 0.03, 0.05]`. FULL completes the premultiplied scene with that radiance before the existing tone curve and sRGB output. Native input completes only canonical RGBA-zero, depth-one, motion-zero texels. Constant infinity has depth one and zero unjittered motion, including camera rotation. Partial, malformed and nonfinite records are not relabelled as sky. The added test-only source-motion binding lets normalization check the same canonical-clear condition.

The three arms are FULL, MFX50 with background reactive one, and MFX50 with stable-background reactive zero. The two native arms have identical radiance, geometry, depth, motion, exposure, mip policy, eight-phase jitter, and frame25 cut. Reactive zero requires previous accepted history with unchanged declared domain. First frame, cut, extent/gap and background/policy identity changes reset; rejected identity changes leave the old state intact. Geometry with invalid motion keeps reactive one.

In the declared opaque domain, finite nonnegative vendor RGB may reconstruct across current geometry/background and depth edges. Vendor alpha is ignored; output alpha is one because the scene domain is opaque. Nonfinite or negative vendor samples use the independently composed current/background fallback. Malformed source samples retain conservative fallback and do not receive native replacement. This cannot provide transparent output coverage or a general environment-sky implementation. Public unsupported BLEND, overlay, world-text, bloom and cooked-output admission is unchanged.

CPU controls validate both new shaders and the FULL output shader, original transparent source identity, finite bounded background values, and domain-history identity transitions. One ignored GPU boundary control has 24 cases, one submit/map and 122,880 readback bytes. Its cases include background policy/first frame, opaque and mixed-depth coverage, MASK hole, missed thin foreground, partial/malformed clear records, invalid geometry motion, nonfinite current/native values, and fallback. Alpha, depth, motion and reactive values are exact; positive RGB storage permits at most one adjacent binary16 value against independent CPU RNE. This is a storage bound, not a visual threshold.

The later ignored material scene retains 32 frames per arm, 96 scene submissions plus 15 display/raw readbacks: 111 submits, 15 maps, 64 native encodes, 239 explicit command buffers, 15 images, 960x540. Raw native frames16/24 remain selected. All maps stay below25MiB and the output ceiling remains128MiB. Its original guard mask is explicitly a transparent-policy counterfactual, not the opaque adapter's actual selection mask. GPU execution requires a separate reviewed grant; CPU qualification does not establish image quality.
