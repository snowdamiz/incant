# Complete native IK snapshots and controls for Rust/Wasm

The additive `incant_animation_ik_v1` namespace gives ordinary native modules the complete pre-command animation pose plus every ordered IK constraint, and queues target/pole/weight changes through the same native structural transaction as TypeScript. Operations 44–46 are reserved for length, copied read and control. Operations 0–43 and all their prior wire layouts stay unchanged.

## Contract

`Tick::animation_ik` returns borrowed views only after checking the entire outer frame and its nested v4 pose frame. Owners are canonical ascending IDs and must occur in the pose frame. Each owner has at most 32 distinct constraint IDs; declaration order is meaningful and preserved. The whole frame admits at most 4,096 constraints. Chain indices are distinct and less than 4,096; coordinates are finite model-space values within ±1e9 and weight is finite in [0,1]. A mutable target does not grant permission to change sealed chain topology or constraint identity.

The frame is a 24-byte `INCIK001` header, a complete unchanged v4 pose frame, then 104-byte constraint rows. The 88-byte control payload identifies owner and constraint, target, pole and weight. All lengths, reserved fields, membership and numeric ranges validate before borrowed views or native publication. The copied boundary remains little endian, safe for unaligned guest storage and bounded by existing transfer/callback quotas.

Both static wasm2c and development Wasmtime hosts capture the same accepted native pre-command state. Repeated reads during one callback remain unchanged even after a queued control. Authorized malformed, over-quota or unsupported calls poison the whole callback, including when the guest catches the error; prior accepted numeric, structural and log state remains intact. Stale epochs cannot poison a different live callback. Constraint existence is checked against the final native declaration graph before a tick publishes.

Every v1–v4 legacy pose length/read import still refuses any committed IK. Populating the new complete-frame cache does not bypass those eight refusals. Nonzero compound graph fades require another complete-pose protocol; when integrated with the grouped-fade lane, its private v4 encoder rejection must remain active. This API does not flatten compound interpolation into an apparently complete pose.

## Observable checks

The actual generated Rust guest runs 20 ticks in both hosts against a separate typed native oracle. It retains ordinary clip, pair and eight-sample weighted-tree data together with ordered IK rows, changing target, pole and weights at accepted tick boundaries. A successful staged-prefix control establishes that each failure case reaches real numeric, structural, logging and IK work rather than failing before the intended boundary. Capacity, legacy-import, invalid number/identity, quota, late-command, callback and trap cases then preserve prior accepted state. Raw imports additionally exercise malformed addresses, lengths, epochs and no-copy refusals.

The public proof uses `tools/probes/native-wasm-animation-pose-export.py --ik`. It imports a mathematical glTF chain and real Rust module through public tools, authors the scene through `incant_cmd`, verifies Undo/Redo and journal reopen, and compares every complete record against `incant_cook`'s independent typed oracle. It then performs an ordinary fresh wasm2c export, removes only that proof's source/cache/build/debug-map inputs, and runs the copied player three times. Each run checks 252 public vector assertions and 4,140 scalar log observations; exact runtime diagnostics qualify every negative control. All three fresh runs passed with exact development log/PCM equality. All fifteen precise refusals passed: seven in development, seven in the packaged player, and the existing unsupported static-module checkpoint. The actual player is 9,869,152 bytes (SHA-256 `54a18440b32eef62fe92f700d8da8d7de7ca1d30431122087ffc2e991eb06dec`).
