# Authored iOS project archives

The separate `tools/export_ios.py` route freshly compiles a public-authored
TypeScript project into an unsigned iOS CPU runtime static library and a cooked
binary data package. The supported destinations are ARM iOS simulator and ARM iOS
device, produced by the pinned ARM macOS engine toolchain. This does not retarget a
previous executable cache. The ordinary desktop exporter retains host-equals-target
admission, Android remains denied, and mobile static Wasm export remains unsupported.

The cooker prepares the same checked scene and immutable script bindings as the
native project path, resolves the bounded TypeScript import graph with the pinned
Node/SWC compiler, and compiles the captured CommonJS and hardening module afresh
for the reviewed bytecode ABI. The receipt binds the actual producer, exact
destination, ABI/configuration, source bundle, bindings, generated bytes and scene.
Only the build-only ScriptBuild route accepts the destination; it cannot execute as
a producer-runtime CompiledScript or accept a project-provided executable cache.

The existing player build script gains explicit INCANT_MOBILE_PROJECT and optional
INCANT_MOBILE_PROJECT_SCENE selectors. They require project/mobile-ffi features and
reject conflicting desktop, standalone-script and static-module selectors. Runtime
startup uses the existing bounded synchronous C ABI and compiled trusted bytecode.
The resolved normal dependency graph excludes the cooker, document, command bus,
agent, source compiler and JIT. Build dependencies remain build-only.

Each archive build uses fresh private storage, the shipping profile, fat LTO,
optimization level 3, one codegen unit and panic=abort. Actual destination rustc
commands are audited separately from host build tools. The current immutable base
uses both fixed Rapier kernels with enhanced-determinism and parallel enabled;
this records the linked feature contract, not a new cross-device determinism or
performance result. Per-project kernel selection is a separate integration.

The runtime directory contains the stripped archive, stable C header and cooked
data only. Separate symbols retain the unstripped archive and build symbol
metadata. Unlinked archives retain unused QuickJS parser definitions; the actual
C/Swift application links must use dead stripping and independently demonstrate
that those parser definitions are absent. The archive exporter records compilation
only and never claims target execution. Raw compiler, SDK, strip, section and
symbol tool commands and streams accompany their derived audit results outside
the runtime package.

The public fixture creates its assets, TypeScript sources, inputs and attachments
through incant_cmd transactions with provenance. Three separate source-writing
transactions respect the existing one-write-per-transaction bound. Undo and Redo
cover all three writes and the attachment/input transaction, then a fresh public
RPC process reopens the editor-default journal with --journal. Two entry modules
share a transitive helper; three stable-ID instances have distinct immutable props.
A captured PCM tone makes nonzero audio independently observable.

The typed runtime oracle accounts for prior-tick committed velocity before each
script callback. Every twelve-tick run checks all 36 full log records and 72 selected
vector observations, including Unicode props, binary64 bit patterns, exact wide
BigInt arithmetic, the float32 rounding boundary, disabled source evaluation,
held/released input and final world positions. A second module deliberately fails
after the first module staged writes; the package evidence checks its narrower
no-success-report/no-PCM publication boundary, while native transaction tests own
atomic prefix rollback evidence.

## Measured result

Both fresh public exports pass on the immutable `b46d351a` composition of the
accepted compiler and mobile library. This producer result precedes current-main
integration. The simulator export took 428.4 seconds; the successful device export
took 384.7 seconds. The first device Cargo process also reported a successful
build, but a user interruption stopped its wrapper before exit capture and export
publication. That attempt remains qualified as interrupted, with its logs, generated
producer and archive retained. Only the unfinished device export was rerun; the
successful simulator archive was reused.

| Target | Archive / actual caller result |
| --- | --- |
| ARM iOS simulator | 14,512,272-byte runtime archive; actual C and Swift execution, 33 commands / 20 controls |
| ARM iOS device | 14,507,608-byte runtime archive; unsigned C and Swift linking and symbol audits, 8 commands / no execution |

The six fresh simulator positive processes each run twelve ticks, compare all 36
full records and 72 observations with the independent native oracle, and reproduce
exactly 76,800 nonzero PCM bytes. Fourteen additional controls establish exact guest
failure/checksum errors, malformed request status, and unchanged create-only output.
The target was a disposable iPhone 18 Pro / iOS 27.0 simulator, operated through
`simctl spawn`; shutdown and deletion both completed successfully. The archive's
object metadata includes minimum versions 14.0 and 27.0. Linker warnings from the
legacy caller's 15.0 request are retained; there is no older-iOS compatibility claim.

The actual linked C and Swift executables contain bytecode runtime and public ABI
symbols, and omit the audited source-parser definitions. The guest also verifies
that eval and Function cannot compile code. The mobile report does not expose a
source-parsing boolean; the executable audit and guest controls are the evidence.
The runtime package is unchanged across all calls. Its private project, source,
cache, journal and fresh build directories were absent before the runs, and the
newly produced source maps were deleted with recorded hashes. Proof snapshots and
symbols are retained separately outside the runtime package.

Generated Rust producer arrays were captured before normal private-build removal.
Their bytecode/hardening hashes were independently recomputed, and the two target
manifests differ only in their exact destination. Both fresh cooks produce the same
scene, source catalog and script bindings. All 11,856 tracked/new frozen source
inputs remained unchanged through both completed builds and caller runs.

The [durable packet](evidence/authored-ios-project/proof.json) retains 479 artifacts
in a deduplicated lossless archive and hash-binds ten larger external binary files,
including earlier audit/interrupted-attempt archives. Its three independent source
reviews and [final independent execution review](evidence/authored-ios-project/final-review.json)
are accepted. Eleven cooker
cases and 181 compiler/runtime cases pass, as do three-package all-target Clippy,
nine exporter Python cases, strict TypeScript, normal-dependency guard, conventions,
formatting and diff checks. Earlier fixture mistakes are retained: an absent
headless path, a missing required audio field, the existing one-source-write
transaction bound, and an oracle that initially used current rather than prior
committed velocity. None is counted as a successful execution.

This remains a CPU archive/package route, not an Xcode app generator, mobile
window/touch/device-audio host, signed distribution, physical-device performance
measurement or phase gate. iOS simulator execution and unsigned device linking
are distinct results; Android execution admission remains closed.


## Reproduction

From the pinned toolchain environment, create a fresh project through the public
probe before exporting. Each output path must be new.

```sh
python3 tools/probes/authored-ios-project/prepare.py /absolute/prepared \
  --binary /absolute/incant_headless
python3 tools/export_ios.py /absolute/prepared/authoring/game.json \
  /absolute/simulator --target aarch64-apple-ios-sim --evidence /absolute/sim-build-evidence
python3 tools/export_ios.py /absolute/prepared/authoring/game.json \
  /absolute/device --target aarch64-apple-ios --evidence /absolute/device-build-evidence
```

Hash each actual export.json, then pass that hash with `--export-sha256` to
`tools/probes/authored-ios-project/verify.py`, alongside `--prepared`, `--export`,
and a new `--output` directory. Run the simulator with `--remove-authoring` only
after both exports finish. The device invocation then verifies that the private
authoring directory remains absent and performs unsigned links only.
