# Experimental GPU-only color reconstruction

This default-off `experimental-taau` candidate is a bounded comparison, with native diagnostic execution but no appearance acceptance or performance result. The first image capture was blank due to a display-grid mapping error. The corrected `79ec71b0` capture contains the scene but failed direct review for staircase silhouettes, broken/thickened wires and moving outlines; static frame16 also fails, independently of the expected cut/first-frame spatial limit. It starts from main397 `406a93e3`. E046–E049 and their exact sign-sample failures remain separate, unchanged evidence. This path does not replace their centroid oracle or claim to explain cross-process texture-sample differences.

The concrete hypothesis is that output-resolution filtered color history, a reconstructed current sample and 3x3 variance clipping can improve moving detail without the private separated route's CPU readbacks/admission. The existing production fixed-resolution temporal shader already uses depth-admitted bilinear history and a 3x3 neighborhood; it is not the private first-match/2x2 algorithm. This candidate adds a distinct output-resolution reconstruction path rather than relabelling either implementation.

`Renderer::enable_temporal_upscale` prepares nine pipelines at startup (eight center-sampled OPAQUE/MASK material keys and one reconstruction). `RetainedScene` enables a separate owner, explicitly prepares the output extent, and reuses existing object motion, camera cuts, extent changes, lighting reset and accepted-submission chronology. One command encoder/submission performs input geometry, motion, reconstruction and display. There is no CPU pixel admission or readback in this renderer path. Cold WGSL compilation and bounded per-frame bind-group/uniform preparation remain; this is not an allocation-free or stall-free claim.

The input is single-sample, opaque/MASK, scene-linear premultiplied HDR with explicit perspective-center continuous material varyings. All five material texture samples still precede alpha discard, using production PBR bindings/evaluation. Motion MASK sampling is already center-based. Ordinary centroid/4x, 2D, fixed temporal and MetalFX sources remain unchanged. The first slice explicitly refuses partial viewports, pixel cameras, BLEND, sprites, text, SSAO, bloom and cooked shader mode. A dedicated cooked family is required before shipping adoption.

Current color uses a fixed separable 3x3 Lanczos-2 footprint around the unjittered output location in input space, normalized and clamped to its finite current neighborhood. History uses a 4x4 Catmull–Rom footprint, 3x3 YCoCg mean/variance clipping, bounded premultiplied alpha and a fixed radiance-reaction policy. The first executed policy required every nonzero history color tap to have compatible depth, so a different-depth or clear outer tap discarded all history. The current source correction separates positive 2x2 bilinear depth confidence from the complete finite 4x4 signed color filter. Incompatible depth weights reduce confidence without renormalization; zero confidence refuses history. Depth tolerances, reconstruction/clipping/reaction constants and jitter remain unchanged. This correction is not yet executed. An entirely empty current3x3 still refuses history; both its zero alpha bounds and lack of current object motion make a simple background-history bypass unsafe. Entirely missed thin features remain an explicit limitation.

## Coordinate and ownership contract

Input jitter samples are internal pixels, positive right/down. `jitter::ndc` maps them to `[2*x/width,-2*y/height]`; conversion to texture UV flips Y back. Existing motion.xy is **previous jittered UV minus current jittered UV**, normalized to the current input rectangle. Thus unjittered output reprojection uses `motion.xy + (current_jitter - previous_jitter)/input_extent` exactly once. Current color lookup uses `output_uv*input_extent + current_jitter`.

Motion.z is the selected surface's **expected previous projection depth**. The actual current-depth attachment chooses the nearest current surface; motion.z never chooses it. History stores output-sized current depth/support alongside output-sized unjittered color. Previous depth is therefore read in that same output coordinate domain, not from the old jittered low-resolution texture. Invalid/new current owners cannot borrow a neighbor's history. Color/support and frame metadata publish only after accepted queue submission; failed preparation consumes no sequence, phase or history slot.

Two RGBA16Float color and two RG32Float depth/support histories account for 32 bytes per output pixel: 16,588,800 bytes at960x540, with a64MiB history limit and at most two histories during an explicit extent transition. Input frame and motion attachments add 36 bytes per720x405 pixel, giving27,086,400 logical bytes for these candidate textures at75%, excluding output, scene assets, shadows, allocator/driver overhead and queued old commands. These are allocation arithmetic, not measured device residency.

## Comparison and controls

Four CPU controls cover actual production camera/object projections in both projection types and odd extents, shader parsing/validation and center/MASK contract, checked history capacity, and signed cubic reconstruction. The original eleven-mode native control passed at its earlier source. The successor fifteen-mode control changes the named outer-depth policy and adds partial/zero central support and nonfinite support cases. Two CPU controls validate an independent polygon-area oracle and a source-deleted cooked fixture. A new ignored retained-raster control uses20 tiny64x64 draws:16 static frames, object and camera translation, cut and fresh same-pose reset. It saves actual input color, current depth, motion and history, checks raster point coverage except explicitly recorded edge ties within1e-5 output pixels, and compares frame9 against frame1 at the same phase using analytic polygon/pixel area. Cut/fresh equality and vacated-region clearing are required; missed thin-strip coverage is retained rather than hidden. These new controls have not yet executed.

The existing opaque material stage and exact32-frame static→camera/object motion→cut schedule supply four arms at960x540: ordinary full4x, spatial75%, candidate75%, and MetalFX75%. Every display frame is saved as PNG; five frames per arm also retain raw RGBA. Whole motion must be viewed for crawl, thin geometry, trails, disocclusion, cut convergence and coverage fringes. A failed extent submission checks accepted chronology without writing/submitting. The small numerical control must pass before the full sequence.

The genuine full4x reference uses ordinary `draw_scene`. Existing retained native submits intentionally select1x even on a Four renderer; this is documented/tested production policy, not changed here. The full4x arm rebuilds its CPU scene preparation, so the comparison cannot support CPU frame-time claims. A separate invocation records GPU timestamps for the same four sequences without image readbacks. `SceneResolve` measures the candidate reconstruction; the first frame includes resource initialization. The original and corrected captures remain rejected appearance results; no quiet timing run is authorized. After source/CPU review, the tiny successor must pass before another full image sequence. Root owns direct pixel review; numerical success cannot approve appearance.

## Pinned upstream basis and licenses

Primary source was inspected at these exact commits on2026-10-17. The shader is a compact independent expression of the mathematical reconstruction recipe, not a wholesale engine port; borrowed algorithm structure is marked here and in the shader. No upstream reprojection was copied over our object-motion contract.

- [Bevy85503941 TAA](https://github.com/bevyengine/bevy/blob/85503941e488152711a4695bbe248e9ed9f453fc/crates/bevy_anti_alias/src/taa/taa.wesl) supplies the Catmull–Rom history/YCoCg variance-clipping comparison. [Its ordinary UV output](https://github.com/bevyengine/bevy/blob/85503941e488152711a4695bbe248e9ed9f453fc/crates/bevy_pbr/src/render/forward_io.wesl#L98-L108) has default perspective-center interpolation; its TAA excludes MSAA. [MIT notice](licenses/gpu-color-taau/bevy-MIT.txt) is retained. Bevy marks its copied Playdead helpers separately; no such helper source is copied here.
- [Filament9680e59f TAA material](https://github.com/google/filament/blob/9680e59f3fae866ef8f801524e77dd6fbbf760d3/filament/src/materials/antiAliasing/taa/taa.mat) supplies the current unjitter/reconstruct comparison. Its shown matrix/depth reprojection does not replace our moving-object vectors. [Jitter/extent handling](https://github.com/google/filament/blob/9680e59f3fae866ef8f801524e77dd6fbbf760d3/filament/src/PostProcessManager.cpp#L2908-L2959) binds actual viewport dimensions and explicit Y convention. [Apache2.0 license](licenses/gpu-color-taau/filament-Apache-2.0.txt) is retained.
- [Godot81ab961f forward UVs](https://github.com/godotengine/godot/blob/81ab961f91066a63bcbf3ec340962bb1a1ada558/servers/rendering/renderer_rd/shaders/forward_clustered/scene_forward_clustered.glsl#L912-L914) are also ordinary center-interpolated UVs, with implicit material sampling. Its [upscale orchestration](https://github.com/godotengine/godot/blob/81ab961f91066a63bcbf3ec340962bb1a1ada558/servers/rendering/renderer_rd/forward_clustered/render_forward_clustered.cpp#L2557-L2636) separates input color/depth/velocity from output resolution.

- [FSR2 1680d1ed depth confidence](https://github.com/GPUOpen-Effects/FidelityFX-FSR2/blob/1680d1edd5c034f88ebbbb793d8b88f8842cf804/src/ffx-fsr2-api/shaders/ffx_fsr2_depth_clip.h) demonstrates positive bilinear geometric confidence separate from color filtering. This local correction does not implement its reconstructed previous-depth, locks or reactive passes and is not an FSR2 equivalence claim. [MIT notice](licenses/gpu-color-taau/fsr2-MIT.txt) is retained.

These facts do not prove centroid or implicit LOD caused Incant's two differing sign samples. Implicit texture LOD is normal in all three engines. Actual compiled PSO/texture evidence remains necessary for that separate question. An actual center-coordinate sampling experiment would differ from the prior center-gradient experiment, which retained centroid lookup coordinates; it is not silently folded into the old oracle.
