# Compatible static-model refresh in native Play

Native Play can refresh geometry, PBR factors and embedded image content of an already bound static model without replacing the running world or JavaScript VM. Model and texture changes stage as one complete catalog; cache decoding and GPU preparation occur outside authoring locks. Final publication rechecks committed revision, Play generation, world/catalog/topology/binding authority and model-backed navigation dependencies before swapping prepared owners. Refusal retains the complete prior live catalog and reports an error. A committed incompatible authoring edit remains committed; its live admission fails explicitly.

The first slice preserves asset IDs, paths/import interpretation, model scene/node layout and local transforms, primitive/material assignments and interpreted texture-role bindings. Bounded vertex/index buffers, including triangle connectivity, may change or grow/shrink. Both old and new models must be static: animation/skinning, changed node/scene/primitive/material binding structure or counts, changed IDs and baked navigation sources refuse. Explicit colliders have authored primitive dimensions; animation/IK/root-motion catalogs require animated models and are outside this slice. GPU preparation rebuilds geometry and draw bounds. The numerical control observes changed geometric coverage, not isolated shadow-bound fitting. The original texture-only admission API still refuses changed models.
