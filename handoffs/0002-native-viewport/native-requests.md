## R1. Traffic lights: set y to 22 (keep x at 14)

`editor/app/src/main.rs`, window config:

```rust
traffic_light_position: cfg!(target_os = "macos")
    .then_some(tauri::utils::config::LogicalPosition { x: 14., y: 22. }),
```

Why: tao 0.37.1 (`inset_traffic_lights` in `platform_impl/macos/view.rs`) does not
treat `y` as a distance from the top. It sets the titlebar container height to
`close button height + y` and leaves each button's vertical offset inside that
container unchanged. So the current `y: 14` does not centre the lights in the
40 pt titlebar.

Measured with a temporary experiment build (environment-variable override, never
committed, source reverted) and window-only captures at 1280×800 pt:

| Configured y | Light centre from window top | Light top edge |
| --- | --- | --- |
| 14 (current) | 11.75 pt | 5 pt |
| 18 | 15.75 pt | 9 pt |
| 20 | 17.75 pt | 11 pt |
| 21 | 18.75 pt | 12 pt |
| **22** | **19.75 pt** | **13 pt** |

The titlebar logo centre measures 19.75 pt and the bar is 40 pt tall, so y=22
aligns the lights with the logo and the project name to within one device pixel.
The mapping is linear: light centre = y − 2.25 pt. x=14 gives a 14 pt left margin,
which nearly matches the 13 pt top margin, so x stays.

Horizontal extent with x=14: red starts at 14 pt and green ends at 73.5 pt. The
reported `leadingInset: 78` stays correct.

Verify: capture the window and check that the red light's vertical centre equals
the logo's vertical centre. Also check after a window resize and after leaving
fullscreen; tao re-applies the inset in `windowDidResize`.

Evidence: `screenshots/titlebar/` (before at y=14, after at y=22).

## R3. Inspector field order: pass declaration order through the bridge

`editor/bridge/native.ts` builds `ComponentSchema` without `order`, so the UI
falls back to alphabetical order. Transform therefore reads Rotation, Scale,
Translation. The JSON schema already carries declaration order in `required`:
`["translation", "rotation", "scale"]`.

Requested: set `order: schema.required ?? []` when building `schemas[type]`. The
UI already honours `ComponentSchema.order` and appends any remaining keys
alphabetically. Optional: emit `"x-incant-widget": "quat"` on `Transform.rotation`
so the inspector can label it as a quaternion explicitly. It already shows X, Y, Z
and W today.

Untitled fields are now humanised in the UI, so "translation" reads
"Translation". The duplicate "Transform Transform" header is fixed in the UI.

## R4. Viewport clear colour (design recommendation, low priority)

The renderer clears to linear 0.03, which is sRGB #303030. This was measured
exactly in both the native capture and `incant_headless screenshot`. It is
correct, but it is the largest and brightest flat area in the window. It is also
neutral, while every other surface uses the cool graphite palette: islands
#131418, canvas #0b0c0f.

Recommended clear: sRGB #1b1d22, which is linear `r: 0.01096, g: 0.01230, b: 0.01600`.
That keeps the viewport a distinct stage, slightly lifted from the islands, and
keeps strong contrast for the light grey geometry. Apply it to the native path and
the headless screenshot alike, so they stay pixel-identical. If the director
prefers neutral mid-grey for judging values, keep #303030. This is a taste call,
not a defect.

## R5. Anti-aliasing for diagnostic geometry (low priority)

Cube edges show stair-stepping in native captures and in
`screenshots/headless/headless-1920x1080.png`. 4× MSAA on the colour and depth
attachments, resolved into the surface texture, would remove it at negligible
cost for this scene.

## R6. Titlebar double-click should honour the macOS preference

Native double-click on the titlebar currently always toggles zoom. On this Mac
`defaults read -g AppleActionOnDoubleClick` reports that the key does not exist,
which means the system default, Maximize (zoom). Behaviour here is therefore
correct: zoom filled the visible frame at 1512×874 pt, and a second double-click
restored the exact prior frame.

Requested for correctness elsewhere: on macOS, in `window_action(Maximize)`, read
`AppleActionOnDoubleClick` from the global domain. Map `"Maximize"` or a missing
key to zoom, `"Minimize"` to `minimize()`, and `"None"` to doing nothing. On macOS
the UI sends `window.maximize` only from a titlebar double-click, because it draws
no caption buttons there, so the host can apply the preference without a contract
change. Also treat the legacy `AppleMiniaturizeOnDoubleClick = 1` as Minimize when
the newer key is absent.
